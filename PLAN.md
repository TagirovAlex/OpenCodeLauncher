# OpenCodeLauncher — план разработки

> Десктопное приложение **Windows Forms / C# / .NET 8 (LTS)** для управления OpenCode-сервером.
> Работа ведётся по правилам для агента из **`AGENTS.md`**.

## 0. Проверенное окружение

- **OpenCode 1.18.35** установлен. Ключевые команды:
  - `opencode serve --hostname <IP> --port <порт>` — headless-сервер с веб-интерфейсом; **проект берётся из рабочей директории** (позиционный аргумент не поддерживается — проверено);
  - запуск: `opencode.cmd` из npm-каталога (`.cmd`, не `.ps1`); stdout содержит строку `opencode server listening on http://...`;
  - `opencode [project]` — запуск TUI;
  - `opencode session` — управление сессиями;
  - `opencode stats` — статистика токенов/стоимости;
  - `opencode providers` — провайдеры и ключи.
- **.NET SDK 8.0.418 и 9.0.313** установлены. Целевой — **.NET 8 (LTS)**.

## 1. Концепция

**OpenCodeLauncher** — GUI для запуска и мониторинга OpenCode-сервера:

- запуск `opencode serve` для выбранного проекта на выбранном IP-адресе (из списка доступных сетевых интерфейсов, включая Tailscale) и порту;
- проверка состояния сервера (healthcheck) и открытие веб-интерфейса;
- управление конфигурациями (модели, провайдеры, ключи, промпты);
- мониторинг: статус запущенных сессий, логи, статистика токенов.

**Ключевой сценарий:** выбрать проект → выбрать Tailscale-IP → запустить сервер → подключиться с телефона через Tailscale → видеть состояние проекта в браузере.

## 2. Правила для агента

Все обязательные правила поведения агента — в **`AGENTS.md`**. Главные:

1. **Запрет выхода из папки проекта** — никаких чтений/записей/команд за пределами корня `C:\Github\OpenCodeLauncher`.
2. **Временные файлы — только в `temp/` проекта** — никаких системных временных папок.
3. **Формы WinForms — с поддержкой визуального редактора Visual Studio** (`partial class` + `<Имя>.Designer.cs`).
4. **Настройки приложения — в папке рядом с exe** (`AppContext.BaseDirectory`), без `%APPDATA%` и реестра.

## 5. Дорожная карта

### Фаза 0 — Фундамент
- Создать решение и 3 проекта, подключить Serilog, настроить `.gitignore` (включая `temp/` и артефакты сборки).
- Папка `temp/` — временные файлы и логи.
- Базовые сервисы: `AppSettings` (сохранение **в папке приложения рядом с exe** — `AppContext.BaseDirectory\settings.json`), логгер.
- Первая форма создаётся по дизайнер-совместимому паттерну: `partial class MainForm` + `MainForm.Designer.cs` с `InitializeComponent()` — чтобы форма открывалась и редактировалась визуально в Visual Studio.
- Проверить флаги: `opencode serve --help` (убедиться, что позиционный аргумент `project` работает с serve).
- **Критерий:** решение собирается, приложение открывает пустое главное окно.

### Фаза 1 — MVP: запуск сервера (главная ценность)
- `NetworkService`: список интерфейсов и IPv4 с пометкой «Tailscale», выбор по умолчанию.
- `ProcessService`: запуск `opencode serve` с `WorkingDirectory = проект` (проверено, что проект берётся из cwd), сбор stdout/stderr, graceful-остановка, защита от двойного запуска.
- `HealthService`: HTTP-проверка `http://<IP>:<порт>/` с таймаутом.
- UI-вкладка «Запуск»: выбор проекта (диалог + избранное), выбор IP, порт, кнопки Старт/Стоп, индикатор статуса, лог-панель, кнопка «Открыть в браузере».
- **Критерий:** с телефона в Tailscale открывается веб-интерфейс выбранного проекта.

### Фаза 2 — Конфигурации и профили
- `ConfigService`: чтение/запись конфига OpenCode (`%USERPROFILE%\.config\opencode\opencode.json`) — модели, провайдеры/ключи, промпты (аккуратный merge, бэкап перед записью).
- `ProfileService`: сохранённые «профили запуска» (проект + IP + порт + модель + флаги: `--continue`, `--model`).
- UI-вкладки «Профили» и «Конфигурация» (таблицы + редактор).
- **Критерий:** профиль запускается в 1 клик; изменения конфига видны OpenCode.

### Фаза 3 — Дашборд и мониторинг
- Фоновый мониторинг запущенного сервера (healthcheck каждые N сек, статус в трее/заголовке).
- Список сессий (`opencode session list`), просмотр статистики токенов (`opencode stats`).
- UI-вкладка «Дашборд»: статус, таблица сессий, метрики, логи.
- **Критерий:** при падении сервера UI показывает статус и предлагает перезапуск.

### Фаза 4 — Полировка и релиз
- Системный трей (свернуть, быстрый старт/стоп), автозапуск с Windows.
- Обработка ошибок (opencode не установлен, порт занят, IP недоступен) — понятные сообщения.
- Юнит-тесты Core-слоя (парсинг IP, профили, сборка аргументов запуска).
- Публикация single-file exe (`dotnet publish -r win-x64`).
- **Критерий:** дистрибутив без установки SDK работает на чистой Windows.

### Ключевые решения (проверены опытным путём)
- `opencode serve` **не принимает** путь проекта аргументом — проект берётся из рабочей директории процесса.
- Запуск — через `opencode.cmd` (npm), резолв по PATH: `opencode.exe → opencode.cmd → opencode.bat`.
- **Привязка сервера — `0.0.0.0`** (все интерфейсы), а выбранный IP (например Tailscale) используется как «рекламируемый» URL. Причина: Windows/Tailscale не позволяют достучаться до собственного Tailscale-IP с той же машины (проверено: `Test-NetConnection` к 100.88.102.49:port → False даже при привязке к этому IP), из-за чего healthcheck «падал» по таймауту. Поэтому локальный healthcheck идёт через `127.0.0.1`, а снаружи сервер доступен по выбранному IP.
- Готовность сервера — по строке `opencode server listening on http://...` и HTTP-проверке через loopback.
- Вывод процессов читается как **UTF-8** (`StandardOutputEncoding/StandardErrorEncoding`) — иначе в дашборде кракозябры.
- В панели лога — **таймстампы** `[HH:mm:ss]`.
