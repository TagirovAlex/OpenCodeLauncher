# Правила для агента (OpenCodeLauncher)

Эти правила обязательны для всех агентов, работающих в этом репозитории.

## Критические правила (нарушение запрещено)

### 1. Запрет выхода из папки проекта
- Агент **НЕ имеет права** читать, записывать, создавать или выполнять команды за пределами корня проекта: `C:\Github\OpenCodeLauncher`.
- Это касается любых операций: чтение файлов, поиск, создание файлов, запуск команд с путями вне проекта.
- Исключений нет. Если задача требует доступа к чему-то вне проекта — остановиться и спросить пользователя.

### 2. Временные файлы — только в `temp/` проекта
- Все временные файлы (кэш, черновики, отладочные артефакты, скачанные файлы, логи) создаются **строго** в папке `temp/` внутри корня проекта.
- Категорически запрещено использовать системные временные папки (`%TEMP%`, `C:\Users\...\AppData\Local\Temp` и т.п.) и любые другие пути вне проекта.
- Папка `temp/` не коммитится (в `.gitignore`).

## Архитектура и технологии

- **Платформа:** Windows, **C# / .NET 8 (LTS)**, **Windows Forms**.
- **Архитектура:** MVP (Model-View-Presenter).
  - Бизнес-логика и сервисы — в проекте `OpenCodeLauncher.Core` (без зависимостей от WinForms).
  - UI (формы, презентеры) — в проекте `OpenCodeLauncher`.
  - Тесты (xUnit) — в проекте `OpenCodeLauncher.Tests`.
- **Хранение данных приложения:** все настройки/файлы приложения — в папке рядом с exe (`AppContext.BaseDirectory`, например `settings.json`). Запрещено использовать `%APPDATA%`, реестр и другие системные хранилища.
- **Логирование:** Serilog, логи пишутся в папке `logs/` рядом с exe.
- **JSON:** `System.Text.Json`.
- **Асинхронность:** `async/await` вместо блокирующих вызовов в UI-потоке; отменяемые операции через `CancellationToken`.

## WinForms и визуальный редактор Visual Studio

Формы должны оставаться редактируемыми в дизайнере Visual Studio:

- Каждая форма — `partial class <Имя>Form : Form` + отдельный файл `<Имя>Form.Designer.cs` с методом `InitializeComponent()`.
- Все контролы объявляются и настраиваются в `.Designer.cs` (дизайнер VS сериализует их именно туда).
- **Запрещено** создавать формы полностью кодом (без `.Designer.cs`) — такие формы нельзя открыть в визуальном редакторе.
- Не помещать логику в `InitializeComponent()`; программные настройки UI — в коде формы (например, в обработчике `Load`), не в дизайнерном файле.
- При ручном изменении `.Designer.cs` сохранять совместимость с дизайнером: использовать только дизайнер-сериализуемые свойства и стандартные контролы.

## Стиль кода

- Следовать существующим паттернам проекта; перед изменениями читать затрагиваемые файлы.
- Включённые nullable-типы; понятные имена; без мёртвого кода.
- Минимальные изменения, решающие задачу. Не удалять код, который непонятен, без уточнения.
- Новые файлы создавать только при необходимости.

## Процесс работы

- Перед завершением задачи, если изменялся код: проверить сборку (`dotnet build`) и, где применимо, тесты (`dotnet test`) — с рабочей директорией в корне проекта.
- `temp/`, `bin/`, `obj/` и прочие артефакты — не коммитить.
- Не коммитить и не пушить без явного запроса пользователя.
- Не создавать документацию (`*.md`) без явного запроса (исключение: `PLAN.md`, `AGENTS.md`).
- Команды запуска OpenCode/приложения — с путями внутри проекта либо с путями, указанными пользователем.

## Если правило конфликтует с задачей

При конфликте задачи с этими правилами — **правила имеют приоритет**. Остановиться, объяснить конфликт и спросить пользователя, как действовать.
